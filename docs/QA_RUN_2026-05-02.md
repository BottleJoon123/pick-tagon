- 구형 `유저 본인만 수정` (ALL, public 롤): SELECT/INSERT/UPDATE는 신형 정책과 중복
- **핵심 위험**: `ALL`이므로 DELETE도 허용. 신형 정책 중 DELETE 정책이 없으므로 이 구형 정책이 유일한 DELETE 허용 경로

**실질적 위험:**
- 자기 계정 row 삭제 가능 → picks, event_picks 등의 user_id 참조 FK가 cascade이면 연쇄 삭제, restrict이면 삭제 실패
